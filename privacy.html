Privacy

Updated November 27, 2026.

1. Who handles your data

The operator of the Alisa web chat runs the service and manages its storage. The chat uses browser sessions without a sign-in. See Your data controls for options with your current session and what happens if you lose its cookie.

2. What the chat stores

  • The server keeps chat exchanges with timestamps, replies, language, model and time zone. It may retain summaries, model output and diagnostic details related to an exchange.
  • Alisa's memory includes your preferred name, saved facts, interests, conversation notes and summaries. It can also contain excerpts from recent chats.
  • Your browser stores recent chats and preferences, including language, optional dictation acknowledgment and the time of the last AI reminder. A signed aid cookie connects this browser to its server data.
  • Vercel supplies an IP address and approximate country. The country selects crisis resources. The service uses keyed hashes of IP addresses and browser session identifiers for request limits. It also keeps a daily request count for the whole site.

3. How we use it

We process messages to reply, keep context across visits and apply safety checks. Request counts help limit abuse. When the server identifies a possible crisis it writes an operational event without the message or a user identifier. If only the browser detects a possible crisis, the browser can show help without creating that server event. The exchange may still appear in the stored chat history.

Messages can reveal health, sexual orientation or other private information. Avoid sending sensitive information or private details about other people.

4. Service providers

Vercel runs the web service and Upstash Redis stores server-side data. OpenRouter sends text, chat context and relevant memory to model providers. Chat replies use models from Anthropic, DeepSeek or Mistral AI. Supporting tasks can use other models, including TypeSafe for safety checks and OpenAI for memory search. Providers may process this data outside your country, including in the United States.

Some providers may retain model inputs and outputs or use them to improve models. This depends on the OpenRouter settings for the service, the route and the policy of the provider that receives the request. The chat does not set a zero-retention or data collection restriction in each request to OpenRouter. See OpenRouter's privacy policy for details.

If you choose dictation, your browser may send audio to its speech recognition provider, such as Google in Chrome or Apple in Safari. Alisa receives the transcribed text when you send it. You can type instead.

5. Retention

The chat log holds up to 500 exchanges. By default, older exchanges are trimmed after 90 days when new exchanges are written, and the log expires 90 days after its last write. The operator can configure the log retention period. Saved memory stays on the server until it is deleted. The browser cookie lasts one year. Local history and settings remain until cleared. Request counters expire at the end of their minute or UTC day.

Vercel keeps crisis events in its runtime logs. The retention period depends on the hosting plan. On Vercel Hobby, runtime logs are kept for one hour.

6. Your data controls

While the web chat is temporarily unavailable, open Manage my data on the chat's temporary screen to use these controls.

  • In Settings, change your preferred name or delete individual facts from Alisa's memory.
  • Download my data saves a JSON file with server memory, the stored chat log within its retention window, and the history on this browser.
  • Forget everything deletes the server memory and chat log for this browser session, expires its session cookie and clears its local chat history. You can use it to delete a conversation even when the facts list is empty. Clear chat clears local chat history alone. These controls apply to the Alisa service. Providers can have their own retention rules.

Use Settings to download or delete data while this browser still has its session cookie. If the cookie is lost or expires, the chat cannot reconnect this browser to the old session. The old chat log expires under the retention policy above. Saved memory has no automatic expiration.

For a request about an old session, a saved fact ID and the approximate time of a past exchange from a previous download can help locate the session. Keep your cookie and full chat history private. The operator needs to verify the link to the session before releasing or deleting its data. If the link cannot be verified, the operator will explain the reason where possible.

For requests covered by EU data protection law, the operator responds without undue delay and within one month of receipt. If an extension is needed, the operator will explain why within that first month. An extension can be up to two additional months.

Depending on where you live, you may have additional rights to access, correct, delete or restrict use of personal data, to receive a copy, to object to processing and to lodge a complaint with your privacy regulator.

7. Age

The web chat is intended for adults 18 and older. The browser checks the birth month and year you enter and saves the result or the time of a temporary block. It does not save or send your date of birth.
